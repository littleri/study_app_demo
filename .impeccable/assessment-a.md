# Assessment A — 独立设计评审

评审目标：`src/App.tsx` 所承载的 BookCourse AI 全前端
稳定现场：`http://127.0.0.1:5173/?preview=devices&device=iphone-17-pro&orientation=portrait&quality=fit&chrome=1`
评审条件：iPhone 17 Pro 逻辑视口 `402 × 874 CSS px`；独立新建的 in-app browser tab；未运行 `detect.mjs`，未读取或引用 Assessment B。

## AI slop verdict

**Fail（中高置信度）**。信息架构里有真实产品思考，但视觉语言仍很容易被判断为“AI 生成的教育 App”：紫蓝渐变、浅蓝玻璃底、云朵吉祥物、泛滥的圆角白卡、同规格快捷卡网格、章节报告的英雄数字圆环、多个 tiny eyebrow 同时出现。尤其 `base.css` 将大量 `.card`、`.quick-action`、`.community-book-card`、`.stage-row`、`.metric-card` 统一为“1px 边框 + 10/12px 位移、22/28px 模糊阴影 + 18/20/24px 圆角”，形成典型 ghost-card/card-soup；`--radius-large: 26px`、`--radius-glass: 30px`、`--glass-nav-radius: 32px` 又放大了这种模板感。

第一阶类别反射是“AI 学习产品 = 紫蓝/天空蓝 + 软萌陪伴角色”；第二阶反射是“避免喧闹游戏化 = 轻玻璃、柔和渐变、巨大圆角卡片”。当前两阶都未真正脱离。好消息是品牌资产、原书证据链和首页“今日下一步”足以成为更独特、更克制的设计核心，无需推翻产品骨架。

## 认知负荷

**结论：高负荷，8 项中失败 6 项。**

- [x] Grouping：卡片、section、header 与 toolbar 基本把相关内容放在一起。
- [x] Working memory：课程名、章节、页码和引用位置通常仍在当前屏可见，无需完全依赖记忆。
- [ ] Single focus：首页同时出现主 CTA、三段生成路径、课程入口、四个学习工具、AI 浮球和底部导航；社区浮球还覆盖课程卡。
- [ ] Chunking：章节页一次性展开学习目标、4 个讲解块、多组引用、再次汇总的原文证据、插图、6 个概念和工具栏，纵向瀑布过长。
- [ ] Visual hierarchy：课程主页四个快捷卡同权，报告页“建议”与“下一步”同样醒目；卡片/阴影语言把几乎所有内容都提升到同一层。
- [ ] One thing at a time：学习内容、原文核对、AI 问答、闪卡、练习、笔记、生图和完成章节同时存在，未按“先学—再核对—再练习”分段。
- [ ] Minimal choices：多个决策点超过 4 个可见选项。
- [ ] Progressive disclosure：raw chunk、双页码、所有引用、核心概念、生图入口全部默认展开；高级/调试信息没有进入次级详情。

### 超过 4 个选择的具体位置

- 首页：主 CTA + 3 个课程生成步骤 + 课程行 + 4 个学习工具，主内容区首屏有至少 9 个动作（尚未计入底部导航与 AI 浮球）。
- 社区：4 个课程包 + AI 浮球 + 4 个主导航入口；浮球覆盖第一张课程卡右侧区域。
- 课程主页：4 个同权快捷卡 + 章节入口 + AI 浮球 + 4 个主导航入口。
- 章节页：单一章节内有 6 个核心概念按钮、6 个汇总证据按钮、4 个学习工具动作和 2 个结束动作；同一证据还在讲解块与“原文证据”重复出现。
- 报告页：“查看详情” + 3 个 AI 建议 + 2 个结束动作，共 6 个下一步。

## 情绪旅程

1. **进入首页 — 安心、被陪伴。** “今天，沿着原书继续前进”“今日下一步”和学习路径状态降低了启动压力；这是品牌最吻合的时刻。
2. **上传教材 — 信任要求突然升高。** 大面积留白与隐私 pill 有安抚作用，但巨大的“+”、底部“选择文件”、拍照导入、本地文档是三套近似入口；用户仍不知道点击后是否立刻上传、是否能先预览。
3. **生成阶段 — 从陪伴感跌入工程后台感。** 状态透明是优点，但“PostgreSQL / BGE-M3 / BM25 + pgvector”把学习者拉进实现细节，容易让 Jordan 感到不确定，让家长/学生担忧失败后该怎么办。
4. **章节学习 — 信任峰值。** 每段讲解旁都能回到教材页，这是产品真正的情绪高点：AI 不是黑盒，学习者可以核对。
5. **完成报告 — peak-end 规则被破坏。** 从长章节底部点击“完成章节”后，实测新报告继承 `scrollTop: 314`；报告卡 `y: -186`，“太棒了！”`y: -120`，104px 分数环落在 `y: 5` 并与状态栏/标题区域相撞。用户错过庆祝与总结，结束记忆变成“页面好像坏了”。

## 做得好的地方

1. **原书证据链不是装饰。** 章节讲解包含可点击引用、教材页/PDF 页、原文摘录，并能进入 SourceReader；这直接兑现“可追溯原书证据”的核心承诺。
2. **状态模型较完整。** 首页能区分等待、处理中、需确认、成功、错误；解析页有阶段、进度、后台运行、错误恢复和可感知文本状态，明显优于只放一个无限 spinner。
3. **无障碍基础意识真实存在。** 语义 landmark、可读按钮名称、`aria-current`、`aria-live`、焦点恢复和全局 `prefers-reduced-motion` 已进入实现，不是事后补丁。

## 优先问题

### [P1] 跨屏滚动位置继承，让报告从中段打开

**Why：** 这是核心学习闭环的结束页。用户从章节底部点击“完成章节”后，新屏继承旧 `.screen-content` 的滚动位置，首要总结和庆祝被移出视口，分数环撞进状态栏。它同时伤害系统状态、空间一致性和 peak-end 情绪。

**Fix：** 在 `navigation.nonce` 改变时、屏幕转场呈现前，将 `.screen-content` 同步重置到 `scrollTop = 0`，再移动焦点；仅在明确的“返回上一屏”场景恢复每屏独立滚动快照。为 `lesson → report`、`report → book` 加移动端滚动断言，验证标题和首张卡 `y >= header bottom`。

### [P1] 上传承诺与实际行为冲突，缺少高成本动作确认

**Why：** 上传页写着“确认后再开始 OCR”，但 `uploadSelectedFile()` 选择文件后立即上传并 `startParse()`，然后才进入 `parseReady`。对私人教材、慢网或误选文件，这是信任与错误预防问题；没有取消/替换也会让用户感到被流程绑架。

**Fix：** 改为“选文件 → 本地校验/预览（文件名、大小、页数估计、隐私说明）→ 明确点击开始生成”；提供“替换文件/取消”，解析开始后显示“后台继续、可安全离开、如何停止/重试”。若产品必须自动开始，就删除“确认后”承诺并在点击前明确写出结果。

### [P1] 证据展示把可追溯性变成重复与技术噪音

**Why：** 章节 DOM 同时在每个讲解块显示引用，又在“原文证据”重复 6 条；用户看到 raw `chunk_c2s1_13`、教材页/PDF 页和长摘录。证据本应建立信任，现在却压过讲解主线，并要求学生理解内部索引模型。

**Fix：** 每段只保留一个紧凑的“来自教材第 18 页”证据按钮；点击后在同一上下文展开摘录与页图。页尾改为可折叠“本节 3 个来源”，去重相同 chunk；raw chunk ID 放进“技术详情”，默认不出现。printed page 与 PDF page 只在二者不一致且确有核对价值时并列。

### [P2] 视觉系统陷入 ghost-card/card-grid 模板，削弱产品层级

**Why：** 边框 + 宽阴影 + 高圆角被用于几乎所有内容，紫蓝渐变和吉祥物又在多屏重复。课程主页四个模块、社区卡、报告建议都获得近似权重；这既是明显 AI slop，也让学生更难识别真正下一步。

**Fix：** 采用 restrained product palette：渐变只保留给一个主动作，吉祥物只出现在首页/完成时刻。内容列表和证据改用平面分隔线或轻底色，卡片半径收敛到 12–16px，并取消“1px 边框 + 22/28px 模糊阴影”的组合。建立明确三层：页面背景、任务/阅读面、唯一主 CTA。

### [P2] 移动端触控与文本对比未稳定达到 AA 目标

**Why：** 报告页实测返回按钮仅 `34 × 34px`；CSS 里首页主 CTA `min-height: 40px`、章节证据展开按钮 `28px`、原文翻页按钮 `38px`，均低于约定的 44px。常用 muted token `#73819b` 对白色仅约 `3.93:1`，`#7a879b` 约 `3.64:1`，`#8b98ad` 约 `2.92:1`；首页还有 9–11px 辅助文案。

**Fix：** 统一所有交互 hit area 至至少 44×44px（视觉图标可小，点击盒必须足够）；建立一个通过 4.5:1 的正文 muted token 与仅供非文本装饰的更浅 token。将关键状态/说明抬到至少 12–14px，并在真实半透明背景上复测，而不是只测纯白。

## Persona red flags

### Jordan（第一次使用）

- 首页的第一动作清楚，但进入课程后立刻遇到 `RAG 片段`；处理页还出现数据库、embedding、混合检索术语，Jordan 无法判断这些是否是需要学习/配置的内容。
- 上传页三套近似选择入口让他犹豫；更危险的是“确认后开始”与实际自动开始冲突，他会误以为还有复核机会。
- 没有稳定可见的“这是怎么工作的/上传后会发生什么”帮助入口；浮动 AI 球也没有解释它是否会引用原书、是否会离开当前上下文。

### Sam（依赖无障碍与键盘）

- 语义、焦点和 reduced motion 基础不错，但多个触控/点击目标小于 44px，对低视力与运动障碍用户不友好。
- muted 文本 token 在白色上低于 4.5:1；薄字、9–11px 辅助信息和半透明背景会进一步恶化可读性。
- `ProgressBar` 目前是带 `aria-label` 的 generic 容器，而不是可读出 `aria-valuenow/min/max` 的 progressbar；章节证据与报告状态需要更准确的状态语义。
- 新屏焦点虽移到 `<main>`，但滚动位置没有同步重置；屏幕阅读器与视觉视口会得到互相矛盾的“已到新页面/仍在中段”体验。

### Casey（单手、易被打断的手机用户）

- 首页主 CTA 位于上半屏，底部是四个全局入口；课程的真正“继续”路径并不总在拇指区。
- 章节学习是很长的卡片瀑布，完成按钮在末尾；中断返回后缺少可见的阅读进度/“继续上次位置”策略说明。
- 社区截图中浮动 AI 球覆盖第一张课程卡，固定底部导航又遮住下方内容；在 402px 窄屏上可用内容区域被两个悬浮层同时侵占。
- 上传立刻启动后没有显式取消，慢网或误选时尤其焦虑。

## 次要观察

- “14 天计划 · 125 个页”不自然，应为“125 页”；“课程可信度/目录平均置信度”需要转译为学习者能理解的“已核对原书范围/需要你确认的章节”。
- 社区 hero 在移动端占用接近半屏，首个课程包只露出一部分；发现内容的效率被品牌图压低。
- 报告页把 `82%` 在英雄环和首个 metric 中连续重复，信息收益很低；可以让 hero 总结“已掌握/需巩固”，三项 metric 再提供数字。
- 首页对比其余页面更扁平、更任务导向，是更合适的方向；无需把首页重新卡片化，应反向简化其他页面。
- `role="application"` 会改变部分屏幕阅读器的浏览模式；除非确实依赖应用级键盘交互，优先使用常规 landmark。
- 全局隐藏滚动条会削弱长章节的“还有多少内容”感知；移动端至少需要阅读进度或章节位置反馈。

## 挑衅性问题

1. 如果“原书优先”真是品牌核心，为什么用户在课程主页先看到的是 `RAG 片段` 和 4 个 AI 工具，而不是“今天读原书哪 3 页、AI 帮你做什么”？
2. 如果每个页面只能保留一个高饱和渐变按钮，哪一个动作真正值得它？其余卡片是否都能降为列表或文本链接？
3. 课程生成的透明度是让用户理解“正在做什么”，还是让用户看到“系统用了哪些技术”？这两件事当前被混在了一起。
4. 完成一章后，用户最想感受到的是被夸奖、看懂薄弱点，还是立刻被塞进五个下一步？报告是否应该先给一个结论，再逐层展开行动？

## Assessment A 结论

这是一个**产品逻辑强于视觉系统、证据能力强于学习节奏**的界面。最先修的不是“更漂亮”，而是：让新屏从正确位置开始、让上传承诺可信、把证据从技术清单重构为学习支撑。完成这三件事后，再收敛卡片/渐变/圆角，品牌的温和与可信会自然出现。
