# P2 卡片系统改进方案：A + C

## 目标

以 A「教材编辑器」为全局结构语言：中性页面、扁平阅读面、清晰分隔、唯一主操作；只在首页、解析完成、章节完成、空状态等关键时刻保留 C 的云朵角色与柔和蓝紫品牌感。

本次同时把触控尺寸和文字对比度升级为硬性质量门槛，而不是视觉微调项。

## 当前证据

- `src/styles/tokens.css` 的 `--color-text-muted: #73819b` 在白底上仅约 `3.93:1`；局部 `#7a879b` 约 `3.64:1`、`#8b98ad` 约 `2.92:1`，不满足普通文字 WCAG AA `4.5:1`。
- 现有主色 `#7f74ff` 与白色文字对比约 `3.59:1`，不适合承载小号按钮文字。
- CSS 中仍存在 26–42px 的可交互按钮/图标命中区；项目虽有 `--touch-target-min: 44px`，但被后续局部规则覆盖。
- `.card`、`.quick-action`、`.metric-card`、`.chapter-row` 等大面积同时使用半透明背景、1px 边框、宽阴影和 20–30px 圆角，导致 ghost-card/card-soup。
- `glass.css` 把玻璃效果作为默认容器语言，且全局背景持续出现蓝紫渐变/云朵，陪伴元素没有被限制在关键时刻。

## 设计决策

### 1. 三层表面体系

1. **页面底层**：近中性冷灰背景，不使用连续渐变和全局吉祥物底图。
2. **阅读/任务面**：白色或极浅靛灰的扁平区域，默认无阴影；依靠间距、轻底色和分隔线组织内容。
3. **浮层**：仅导航、Sheet、Dialog、Toast 等真实浮层允许一档小阴影，模糊半径不超过 8px；不再同时叠加装饰性边框和宽阴影。

卡片圆角统一为 12–16px。列表行、证据条目和设置项优先改成同一表面内的分隔行，不再每一项独立悬浮。

### 2. A + C 的品牌分工

- 云朵/品牌插图只保留在：首页今日任务、处理/解析完成、章节完成报告、真正的空状态。
- 普通课程、证据、设置、工具、指标和列表页不使用吉祥物背景。
- 蓝紫只用于主操作、当前选择、焦点和少量状态，不承担大面积装饰。
- 主按钮使用可与白字达到 AA 的实色深靛蓝；删除默认渐变按钮和光晕。

### 3. 颜色与文字 Token

建议基准：

- `--color-primary: #5b55d6`（白字约 `5.65:1`），按下态再加深。
- `--color-text: #20263a`。
- `--color-text-secondary: #4f5e75`。
- `--color-text-muted: #596780`：在白底约 `5.71:1`，在 `#f3f6fb` 上约 `5.27:1`。
- 另设仅供边框、图标底和骨架屏使用的浅色 Token；禁止把它用于正文、标签、placeholder 或状态说明。

所有普通文字、按钮文字、placeholder、标签和说明文字必须达到 `4.5:1`；大字仅在确实满足 WCAG 大文本定义时可采用 `3:1`。禁用态可降低强调，但不能成为唯一状态线索。

### 4. 触控与交互尺寸

- 所有按钮、图标按钮、可点列表行、分页、折叠开关、Chip 操作和表单控件的命中区至少 `44 × 44 CSS px`。
- 主要 CTA 建议 48px 高；图标视觉尺寸可保持 18–24px，但外层命中盒必须 44px。
- 小型文字链接若承担页面操作，使用透明 padding 扩大命中区；正文中的真正内联超链接按语义例外处理。
- 相邻触控目标至少保留 8px 间隔；不能通过负位移或 overflow 裁掉命中区。
- `:focus-visible` 必须清晰，并与新的主色保持至少 3:1 的非文本对比。

### 5. 组件落点

- `tokens.css`：新增表面、文字、边框、阴影、半径和触控 Token，修正主色与 muted 色。
- `glass.css`：保留类名兼容现有 JSX，但把内容容器降级为扁平表面；仅 `.glass-nav` / `.glass-sheet` 等真实浮层保留克制的浮层表达。
- `components/ui.tsx`：`Card` 支持清晰的 surface 语义（默认阅读面；必要时 elevated/celebration），`ProgressBar` 补齐 `role="progressbar"` 与数值 ARIA。
- `base.css` / `home.css` / `responsive.css`：统一 Card、Button、IconButton、行项目、证据、报告、来源阅读器和首页模块；清除后置覆盖造成的 34/38/40/42px 命中区。
- 页面组件仅在语义确实不同或需要限制吉祥物出现位置时做最小 JSX 调整。

## 实施顺序

1. 建立新 Token，并先修复通用 Button、IconButton、Card、ProgressBar。
2. 让旧 `glass-*` 类映射到新表面体系，避免一次性重写全部页面。
3. 扁平化课程、章节、来源证据、报告、社区、设置与指标容器，拆除嵌套悬浮卡。
4. 限制云朵资产到关键状态；将普通页全局渐变背景改为中性底层。
5. 修复所有小于 44px 的交互规则和低对比硬编码文字色。
6. 补充自动化验收，并在 402×874 手机、窄横屏和平板/桌面布局检查关键流程。

## 验收门槛

- `npm run build`、`npm run lint`、`npm test` 通过。
- 代表性流程：首页 → 课程 → 章节 → 来源 → 报告，以及上传流程，在浏览器中无布局回归。
- 可见的非内联交互目标均不小于 44×44px；主要 CTA 不小于 48px 高。
- 普通文字与实际最终背景对比度不低于 4.5:1；主按钮白字也满足 4.5:1。
- 普通内容卡不再出现「1px 边框 + 宽阴影 + 半透明 + 20px 以上圆角」组合。
- 默认内容页无玻璃模糊、无大面积渐变、无全局吉祥物背景；云朵只出现在约定的关键状态。
- 卡片半径处于 12–16px；真实浮层阴影模糊半径不超过 8px。
- 键盘焦点、disabled、hover、active 状态仍清晰；`prefers-reduced-motion` 行为不回退。

## 审核方式

实施者完成后，由主审独立检查 diff、运行全套测试、静态扫描低对比/小触控/ghost-card 模式，并在侧边浏览器逐屏截图核对。发现问题由主审修正后再做最终验收。
